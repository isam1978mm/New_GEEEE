# Notebook Output Inventory for App Patch Planning

This document starts Plan D: patching notebook-derived outputs into the local app in a controlled way.

It is an inventory and planning document only. It does not change the app, backend, pipeline, artifact policy, UI, or tests.

## Goal

The user expectation is that the app should eventually produce the important outputs from the notebook, not only UI summaries.

The correct patch process is:

```text
1. inventory notebook outputs
2. compare app outputs against notebook outputs
3. classify each gap
4. patch missing generation code
5. record artifacts in manifests
6. add tests
7. only then decide what the UI should expose
```

## Important wording

```text
Notebook output = an artifact produced by the Colab notebook workflow.
App output = an artifact generated by the local app pipeline.
Public UI output = an artifact or summary shown/downloaded through the browser/API.
Operator/private output = an artifact stored locally for operator review, not necessarily shown publicly.
```

This inventory is about **generation parity first**. UI exposure is a separate later decision.

```text
[ ] object_index.csv or equivalent exists in app output
[ ] classifier CSV/GeoJSON exists in app output
[ ] KMZ field-map outputs exist in app output
[ ] paid imagery package includes required safe evidence
```

## Patch order

Recommended order after D1:

```text
D2 compare app output tree against this inventory
D3 patch DEM/SAR/QA missing generation
D4 patch canonical feature stack + hypercube generation
D5 patch PCA/object extraction outputs
D6 patch local operator-private package for raw/private outputs
D7 patch KMZ/GeoJSON generation as operator-private artifacts
D8 patch UI only for safe completeness/status, not raw rows
```

## Stop rule

Do not patch UI first. Patch output generation first, then validate files, then decide exposure.
