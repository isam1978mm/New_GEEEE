# V6-E2E-1 Browser Smoke Automation

## Current Status

V6-E2E-1 adds optional browser end-to-end smoke automation for the frozen V6 package flow.

This is a versioned post-freeze follow-up. It does not change frozen V6 generation, scoring, reduction, request-zone, package, backend, or UI logic.

## Scope

The browser smoke test verifies the operator-facing V6 package flow at the frontend boundary:

```text
load app
-> enable operator-private UI setting
-> start local operator session
-> select completed mocked run
-> review safe V6 package metadata
-> generate mocked package
-> review metadata again
-> retrieve mocked ZIP through the controlled route
-> assert private rows and spatial payload bodies are not shown
```

## One-time Local Install

The E2E test imports `@playwright/test`, so the package must be installed in `frontend-v2/node_modules` before `npm run e2e:v6` is run.

From the frontend folder:

```powershell
cd C:\Dev\New_GEE\frontend-v2
npm install
npx playwright install chromium
```

## How To Run

From the frontend folder:

```powershell
cd C:\Dev\New_GEE\frontend-v2
npm run e2e:v6
```

The script runs the local Playwright dependency:

```text
playwright test -c playwright.config.ts e2e/v6-package-flow.spec.ts
```

If Playwright browser binaries are missing, run:

```powershell
npx playwright install chromium
```

Then run the V6 E2E script again.

## Mocking Model

The browser test uses mocked HTTP responses. It does not need a real V6 package, real Earth Engine credentials, real provider data, or real spatial payloads.

Mocked endpoints include:

```text
GET /runs
GET /runs/{run_id}
GET /runs/{run_id}/outputs
GET /runs/{run_id}/operator/private-overlays
GET /runs/{run_id}/operator/v6/package/review
POST /runs/{run_id}/operator/v6/package/generate
GET /runs/{run_id}/operator/v6/package/download
```

The mocked operator-only package responses contain safe metadata only:

```text
validation status
payload count
ZIP entry count
issue count
warning count
package filename
category counts
```

The mocked ZIP retrieval route returns a controlled attachment response and validates that the operator bearer token is forwarded.

## Safety Assertions

The test asserts that the page does not display private payload wording such as:

```text
candidate rows
feature rows
private package input body
spatial payload body
source/package paths
coordinate or geometry payload bodies
```

The E2E test is not allowed to introduce real coordinates, candidate rows, feature rows, provider credentials, or generated V6 artifacts.

## Relationship To Existing Tests

This test complements, but does not replace:

```powershell
python -m pytest tests/unit/test_v6_app_ui_contract.py -q
python -m pytest tests/unit/test_v6_app_flow.py -q
python -m pytest tests/unit/test_v6_deploy_runbook_contract.py -q
npm run build
```

`npm run build` remains the frontend build smoke. `npm run e2e:v6` is the browser interaction smoke.

## Pass Criteria

```text
[ ] browser opens app successfully
[ ] operator session starts with local bearer token
[ ] V6 package panel appears only after private operator UI is enabled
[ ] review metadata shows safe package metadata
[ ] generate action returns generated status
[ ] retrieve action returns controlled ZIP attachment
[ ] no private rows or spatial payload bodies are visible
```

## Rollback

If browser E2E fails after deployment:

```text
1. Keep V6_PACKAGE_FLOW_ENABLED=false in production until fixed.
2. Confirm the backend contract tests still pass.
3. Confirm the frontend build still passes.
4. Open a versioned bug-fix task for the E2E issue.
5. Do not alter frozen V6 generation logic unless the issue is proven to be there.
```
